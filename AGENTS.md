# AGENT.md — French Tarot Web App

This file is the single source of truth for any agent (human or AI) working on this repository.
Read it fully before writing code. If something here conflicts with a request, ask before deviating.

---

## 1. Product summary

A desktop-first web app to play **French Tarot** following the **official FFT rules**
(Fédération Française de Tarot), in **3, 4 or 5 players**, online, with **mixed tables of humans and bots**.

- Players join with a **nickname + room link/code** — no accounts, no sign-up.
- Any empty seat can be filled by a **bot** (3 difficulty levels).
- A game is a **session of N deals** with a cumulative score sheet.
- **UI language: French only.** Code, comments, commits and docs: English.
- Card art: scans of the **Tarot nouveau B.P. Grimaud (1898)**, public domain, digitised by the BnF
  (source and terms in `apps/web/public/cards/SOURCES.md`). Non-commercial use only: a commercial
  release needs a BnF licence or other art.

### Non-goals (for now)

- User accounts, authentication, rankings, long-term history, replays.
- Mobile-first / PWA (the app must remain _usable_ on mobile, but desktop is the target).
- Internationalisation (keep strings centralised so i18n can be added later, but ship French only).
- House rules beyond the room options listed in §5.

## 2. Architecture

```
french-tarot/
├─ packages/
│  ├─ engine/      # Pure TS rules engine — no I/O, no DOM, no network, no randomness except injected RNG
│  ├─ bots/        # Bot strategies (easy / medium / hard), depend only on engine
│  └─ protocol/    # Shared message types + zod schemas (client <-> server)
├─ apps/
│  ├─ web/         # React + TypeScript + Vite, deployed on Vercel
│  └─ party/       # PartyKit / Cloudflare Durable Objects room server (authoritative)
└─ AGENT.md
```

- **Monorepo** with pnpm workspaces. TypeScript `strict` everywhere.
- **Frontend**: React + TypeScript + Vite, static build deployed on **Vercel**.
- **Realtime / game server**: **PartyKit** (Cloudflare Durable Objects). **One room = one table.**
  Vercel serverless functions must NOT be used for game state (no persistent WebSockets there).
- **The server is authoritative.** Clients send _intents_ (bid, discard, play card, declare…);
  the room validates them with the engine, applies them, and broadcasts **per-player redacted views**.
- **Hidden information never leaves the server**: a client only ever receives its own hand, public
  table state, and what the rules reveal (chien in petite/garde, shown poignée, called king when played,
  écart trumps that had to be shown). Never send the full state and "hide it in the UI".
- **Bots run inside the room server**, using the same redacted view a human at that seat would get
  (bots must not cheat by reading other hands).
- Room state is persisted in Durable Object storage after each action so a room survives eviction
  and players can reconnect.

### Engine design rules

See `CONTEXT.md` for the domain language and `docs/adr/` for the reasoning behind these rules.

- Pure, deterministic functions: `applyAction(state, seat, action)` returns `{ ok: true, state }` or
  `{ ok: false, error }` with a closed set of typed error codes — illegal actions never throw.
  (The constructors `createDealFromHands`, for test situations, and `createDealInPlay`, for bots'
  sampled deals, do throw on an invalid distribution: their input comes from our own code, not
  from a player.)
- State is plain, immutable, JSON-serialisable data (no classes, `Map`s or `Set`s), so it can be
  persisted and replayed as is.
- Cards are typed string ids: `S01`–`S14`, `H…`, `D…`, `C…` (11 Valet, 12 Cavalier, 13 Dame, 14 Roi),
  trumps `T01`–`T21`, and `EXC` for the Excuse (ADR-0001).
- Seats are `0…n-1`; the next seat is always `(s + 1) % n`. Counter-clockwise is a UI concern only.
- Two layers (ADR-0002): a **Deal** state machine and a thin **Session** on top (dealer rotation,
  redeals, cumulative score sheet, session end). Seating, nicknames and bots belong to the room server.
- Deal phases: `bidding → (kingCall, 5p) → ecart (petite/garde only) → chelemDecision (if enabled) → playing → finished` (scored),
  plus a terminal `cancelled` (everyone passed, or petit sec). There is no declarations phase: a
  poignée is part of a player's first `playCard` action.
- Randomness: the deal action carries a **seed** (generated by the server with `crypto`); the engine
  owns a small seeded PRNG (ADR-0003). Dealing then follows the physical rule literally.
- `getLegalActions(state, seat)` is the single source of truth for what a player may do. It returns
  **templates**: allowed bids, playable cards (with possible poignées on the first card), and écart
  constraints `{ count, eligible, trumpsAllowed }` — écart combinations are never enumerated.
- `getPlayerView(state, seat)` produces the redacted view: own hand, card counts, bids, contract and
  taker, chien when revealed, shown écart trumps, shown poignées, current trick, **last completed
  trick only**, tricks won per seat, the seat's legal actions, and for the taker their own écart.
  Never: other hands, others' écart, a hidden chien, cards inside older tricks.
- Variant differences (3/4/5 players) live in a **variant config object**, not in scattered `if`s;
  contract differences (multiplier, where the chien goes) live in one **contract rules table**.

### Testing

- **Vitest** for unit tests. The engine must have very high coverage — it _is_ the product.
- **Property-based tests** (fast-check): random legal games always terminate, cards are conserved
  (78 total, 91 points total), scores of a deal always sum to zero.
- Golden tests for scoring with hand-computed examples (including poignées, petit au bout, chelem).
- Bot tests: a bot never proposes an illegal action; full bot-only games run to completion.
- Playwright e2e for a happy path (create room, fill with bots, play a deal) once the UI exists.

## 3. Game rules (FFT official) — reference for the engine

When in doubt, the **FFT official rulebook** wins over this summary. Flag any discrepancy you find.
Primary source and page references: `docs/research/fft-rules.md`.

### 3.1 Cards

- 78 cards: 4 suits (♠ ♥ ♦ ♣) × 14 cards (1–10, Valet, Cavalier, Dame, Roi), 21 trumps (atouts 1–21), and the **Excuse**.
- **Oudlers (bouts)**: the 1 of trump (**Petit**), the 21 of trump, and the **Excuse**.
- Card values:

  | Card                       | Points |
  | -------------------------- | ------ |
  | Oudler (Petit, 21, Excuse) | 4.5    |
  | Roi                        | 4.5    |
  | Dame                       | 3.5    |
  | Cavalier                   | 2.5    |
  | Valet                      | 1.5    |
  | Any other card             | 0.5    |

  Total = **91** points.

- Counting is usually done by pairs; the engine uses half-points (integers ×2 internally to avoid float issues).

### 3.2 Seating, dealing

- Play, dealing and bidding go **counter-clockwise**. The dealer rotates counter-clockwise each deal.
- Cards are dealt **3 at a time** (**4 at a time in 3 players**); chien cards are put aside **one at a time**, never the first or last card of the deck.
- Variant table:

  | Players | Cards each | Dealt by | Chien |
  | ------- | ---------- | -------- | ----- |
  | 3       | 24         | 4        | 6     |
  | 4       | 18         | 3        | 6     |
  | 5       | 15         | 3        | 3     |

- **Petit sec**: a player whose only trump is the Petit (and who does not hold the Excuse) must announce it; the deal is cancelled and redealt by the next dealer. This is mandatory in the FFT rules, so the engine detects it automatically after the deal — it is not a room option.

### 3.3 Bidding

- Starting with the player after the dealer, each player speaks **once**: pass, or bid higher than the current bid.
  A garde contre ends the bidding at once, since nobody can bid higher.
- Contracts (ascending), with multiplier:

  | Contract                | Multiplier | Chien                                                   |
  | ----------------------- | ---------- | ------------------------------------------------------- |
  | Petite                  | ×1         | revealed, taken by the taker, who then discards (écart) |
  | Garde                   | ×2         | revealed, taken by the taker, who then discards (écart) |
  | Garde sans (le chien)   | ×4         | not revealed, counts for the **taker** at the end       |
  | Garde contre (le chien) | ×6         | not revealed, counts for the **defence** at the end     |

- If everyone passes, the deal is cancelled and the next dealer redeals.

### 3.4 Écart (Petite / Garde)

- The chien is shown to all, the taker adds it to their hand and discards the same number of cards face down.
- The écart may **never contain Kings or oudlers**.
- Trumps may be discarded **only if unavoidable**, and any discarded trump must be **shown** to everyone.
- The écart counts for the taker.

### 3.5 5-player specifics — calling a King

- Before the chien is revealed, the taker **calls a King** (any suit). The holder of that King is the taker's secret partner.
- If the taker holds all four Kings, they call a **Dame**; if they also hold all four Dames, a **Cavalier**, etc.
- The taker may call a King they hold themselves (or that is in the chien) → they play **alone** against four.
- The partner is revealed only when the called card is played. The UI must not leak it before.
- The first trick may not be led in the called suit, unless it is the called card itself. The Excuse may always be led; a leader holding only cards of the called suit (besides the Excuse) may lead one of them (case not covered by the FFT text).
- The king call is its own phase, for every contract, right after the bidding. The engine records the partner (`null` when the taker plays alone) when the King is called.
- The view exposes the called card to everyone and the partner only to those who know: everyone once the called card is played or a revealed chien holds it, the holder of the card from the start, everyone at the end of the deal.

### 3.6 Declarations (before or with the first card)

- **Poignée** (showing trumps): optional, open to **any player** (taker or defender), at most one per player, shown when playing one's **first card**.
  - The player shows **exactly** the threshold number of trumps and hides any extra ones.
  - The Excuse may stand in for a trump **only if the player has no other trump** to show instead.
  - The taker may show again, in their poignée, the trumps the écart forced out (FFT p. 6: four Kings and 15 trumps; the p. 5 mention of taking the écart back for the poignée is read as the same case, not as redoing the écart). They count towards the poignée and stay in the écart. Generalised to any trump the écart forced out (our reading). House rule, not in the FFT text: the Excuse may stand in only if these trumps and the hand's together fall short.

  | Players | Simple | Double | Triple |
  | ------- | ------ | ------ | ------ |
  | 3       | 13     | 15     | 18     |
  | 4       | 10     | 13     | 15     |
  | 5       | 8      | 10     | 13     |
  | Bonus   | 20     | 30     | 40     |

  The bonus is **not multiplied** and goes to the side that **wins the contract**, whoever declared it.

- **Chelem** (slam) announcement: only the **taker**, after the contract (and écart) and before the first card; the announcer then leads the first trick. Only offered when the room option is on.

### 3.7 Trick play

- The player after the dealer leads the first trick (except when a chelem was announced). The winner of a trick leads the next.
- **Must follow suit** if possible.
- If unable to follow suit: **must trump**; if trumps were already played in the trick, **must over-trump** if possible (otherwise must still trump lower — "pisser").
- When **trump is led**: must play a **higher** trump if possible, otherwise any trump.
- If unable to follow suit and holding no trump: play any card.
- **Excuse**: may be played at any time, exempts the player from following; it never wins the trick (except the chelem case). If the Excuse is led, the **next card** sets the suit of the trick.
  - Its owner keeps it (it goes to their side) and gives in exchange a 0.5-point card to the trick winner's side. If the owner's side has no trick yet, the card is owed and handed over later; the engine settles the exchange at scoring time.
  - If the Excuse is played on the **last trick** (legal, though discouraged), it goes to the side that wins that trick, with no exchange — except in a chelem, see below.
  - If the taker's side makes a chelem without holding the Excuse, the Excuse stays with the defence and counts 4 points.

### 3.8 Scoring a deal

- Points needed by the taker depend on the number of oudlers in the taker's tricks (+ écart/chien when applicable):

  | Oudlers | Points needed |
  | ------- | ------------- |
  | 3       | 36            |
  | 2       | 41            |
  | 1       | 51            |
  | 0       | 56            |

- Contract is made if `points >= needed`.
- In 3 and 5 players the taker's total can end in a half point; the half point goes to the side that wins (e.g. 40.5 with 2 oudlers fails by 1, 41.5 makes by 1). In 4 players totals are always whole. The breakdown keeps the exact points; only the difference is rounded up (`gap = ceil(|points − needed|)`).
- **Base score `S`**, every term signed **from the taker's side** (ADR-0004):

  `S = c × (25 + |points − needed|) × multiplier + p × 10 × multiplier + c × poignée + chelem`

  - `c` = +1 if the contract is made, −1 if it fails.
  - **Petit au bout**: `p` = +1 if the taker's side wins the last trick with the Petit in it, −1 if the defence does, 0 otherwise — **regardless of contract outcome**.
  - **Poignée**: sum of all poignée bonuses shown at the table, not multiplied, to the side that wins the contract.
  - **Chelem** (all tricks won by one side, not multiplied):

    | Case                          | `chelem` term (taker's side) |
    | ----------------------------- | ---------------------------- |
    | Taker: announced and made     | +400                         |
    | Taker: not announced but made | +200                         |
    | Taker: announced and failed   | −200                         |
    | Defence wins every trick      | −200                         |

    Excuse in a chelem: if the chelem side holds the Excuse, it is played on the last trick and wins it; the Petit then counts "au bout" if played on the second-to-last trick.

- **Distribution (zero-sum)**:

  | Players          | Taker | Partner | Each defender |
  | ---------------- | ----- | ------- | ------------- |
  | 3                | 2S    | —       | −S            |
  | 4                | 3S    | —       | −S            |
  | 5 (with partner) | 2S    | S       | −S            |
  | 5 (taker alone)  | 4S    | —       | −S            |

- The engine produces a **breakdown** of each deal (points, needed, difference, multiplier, each signed term, per-player result) that the score sheet displays.

## 4. Bots

Three levels, all strictly using the redacted player view and `getLegalActions`:

| Level         | Bidding                                                        | Écart                             | Card play                                                                                                                                                                                                                                                                                                  |
| ------------- | -------------------------------------------------------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Facile**    | Simple threshold on hand strength                              | Random legal                      | Random legal card                                                                                                                                                                                                                                                                                          |
| **Moyen**     | Heuristic hand evaluation (oudlers, trumps, kings, long suits) | Heuristic (cut suits, keep kings) | Heuristics: protect the Petit, play the Excuse wisely, give points to partner, avoid giving points to opponents                                                                                                                                                                                            |
| **Difficile** | Same as Moyen                                                  | Same as Moyen                     | Card tracking + Monte-Carlo determinisation (sample hidden hands consistent with known info, play out with Moyen, choose the best average score) with a budget of simulated cards per decision (a few ms, to fit Cloudflare's free plan); in 5 players, Moyen's play until the partner is known (ADR-0005) |

- Bots also handle: king call (5p), poignée declaration, chelem (only when near-certain).
- A bot decision must complete within a bounded time: a few milliseconds, inside the 10 ms of CPU a request gets on Cloudflare's free Workers plan; add a small artificial delay so humans can follow the play.
- Bot strategies must be swappable behind a common `Bot` interface.

## 5. Rooms, sessions and room options

- A host creates a room → gets a **shareable link + short code**. Others join with a nickname.
- The host chooses the **variant (3/4/5 players)** and fills empty seats with bots (level per seat), then starts.
- **Room options** (set by the host before start, defaults in bold):
  - Number of deals in the session: **8** (configurable).
  - Bot level per seat: **Moyen**.
  - Chelem announcements enabled: **on**.
  - Delay between bot moves: **normal** (fast / normal / slow).
- **Session**: N **played** deals (cancelled deals — everyone passed, petit sec — are shown on the score sheet but do not count) with a cumulative score sheet; a final ranking screen at the end; option to start a new session in the same room.
- **Reconnection**: a session token is stored in `localStorage` per room; reconnecting restores the seat.
- **Disconnect → bot replacement**: when a human disconnects, a bot (room default level) plays their seat until they come back; the UI shows that seat as "remplacé par un bot".
- **Leaving**: a player may leave the table for good (« Quitter la table »). In the lobby the seat is freed; during a session a bot (room default level) takes it at once. The player is forgotten (their reconnection token no longer works), and the next human becomes host if they were.
- **Host code** (not a game rule, a tool of the app's owner): typing `tarot("<code>")` in the browser console, during a session, gives the sender an exceptional hand in the next deal only — 12 trumps including the 21, 20 and 19, the Excuse and two Kings (completed with random cards in 3 and 4 players); the rest is drawn from the deal's seed. Refused in the last deal (none follows); forgotten when the session ends or the player leaves; used even if that deal is then cancelled. The code is the room server's `HOST_CODE` Cloudflare secret (at most 200 characters), never in the repository or the web app; unset, every code is refused, and so is every code after 5 wrong ones from a player. The answer goes to the sender only; nobody else receives anything.
- No turn timer (not requested). Do not add one without asking.

## 6. UI / UX

> Visual design (principles, tokens, card rules, motion) is defined in **`DESIGN.md`**. Read it before any UI work.
> Design agents in `.claude/agents/`: `design-system`, `card-artist`, `motion`, `design-reviewer` (run it after every UI change).

- **Desktop-first** layout: table view with the local player at the bottom, opponents around, hand displayed as a fan.
  Must remain usable on a mobile screen, but no mobile-specific design effort for now.
- **Cards**: the Grimaud 1898 scans, served from the repo (never hot-linked), with a drawn corner index over each
  for the fan, and drawn mini cards for small strips. Any other art must be public domain or freely licensed,
  with its source recorded next to it.
- **Game aids** (always on):
  - Playable cards are highlighted; unplayable cards are dimmed and not clickable.
  - Previous trick can be reviewed.
  - Score breakdown is explained after each deal (see §3.8).
- **Declarations are proposed at the right moment**: when a poignée is possible, the UI offers to declare it and lets the player pick which trumps to show (Excuse handling per §3.6). Same for chelem announcement before the first card.
- Clear indications of: dealer, current speaker/player, contract and taker, called king (5p, once revealed), shown poignées, chien (when revealed).
- Animations for dealing/playing/collecting tricks should be smooth but short; never block input longer than necessary.
- All user-facing strings in **French**, centralised in one place (e.g. `apps/web/src/strings/fr.ts`).

## 8. Conventions

- pnpm, TypeScript strict, ESLint + Prettier. No `any` in `engine` / `protocol`.
- Validate every incoming network message with zod (`packages/protocol`).
- Keep the engine free of framework dependencies so it can also run in the browser (e.g. future offline solo mode).
- Small, focused commits; conventional commit messages (`feat:`, `fix:`, `test:`, …).
- Do not add dependencies, features, or rule variants not described here without asking.
